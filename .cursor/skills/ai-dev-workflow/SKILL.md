# AI 编程动态工作流

权威流程图在 `docs/流程图.md`。任务状态库是 `.cursor/workflow/STATE.md`。知识库是 `.cursor/workflow/KNOWLEDGE.md`。阶段验收见 `docs/requirement.md` 第九节。

主控是当前会话。开发、测试设计、验证可以交给子代理。状态文件只由主控写入。

## 会话入口

开发类请求从第三阶段的加载步骤进入，不直接改代码。

1. 初始化执行会话，加载 STATE、KNOWLEDGE、需求与仓库现状。
2. 有未完成任务或检查点：恢复现场，先报告已完成、进行中、就绪、阻塞和建议下一步。
3. 没有检查点：进入第一阶段，从需求输入开始。
4. 状态是暂停时停在等待用户输入：
   - 补充或修改需求：回到需求分析。
   - 确认继续：重新加载检查点，再进入轮询。
   - 暂不继续：保持暂停，不调度。
5. 进程中断或会话重启后，从加载步骤重新进入。把遗留的 `RUNNING` 改回 `READY`，在备注里写明续跑位置。

## 第一阶段：需求分析与拆解

仅在新需求、需求变更，或当前阶段还没有确认过的规格时进入。先读知识库，复用已有决策。

1. 需求输入：业务目标、功能诉求、技术约束。
2. 需求分析：背景、问题、目标。
3. 需求拆解：模块、任务、依赖。
4. 需求规格：功能范围、验收标准、技术方案，写入 STATE 的阶段规格。
5. 需求确认：把规格交给用户。未通过则回到分析并修正。通过后才进入第二阶段。

已确认且用户没有改需求的阶段，跳过本阶段。

## 第二阶段：任务规划

1. 生成当前阶段的开发执行计划。
2. 建立依赖 DAG，写明优先级、前置依赖和可并行分组。
3. 任务清单写入 STATE。每条包含任务 ID、描述、验收标准、负责人、状态、依赖和重试次数。

能并行的任务不要串成一条链。开始新阶段，或要创建、修改、删除 AWS 资源时，计划写入后保持暂停，等用户确认再把任务改为 `READY`。

## 第三阶段：动态执行编排

轮询时只看四种队列结果：

| 队列 | 动作 |
| --- | --- |
| 有依赖已满足的 `READY` | 按优先级选择，最多 3 个，分配后改为 `RUNNING` |
| 没有就绪任务，但有 `RUNNING` | 等待并收集结果，然后继续轮询 |
| 当前阶段任务全部 `DONE` | 进入第四阶段 |
| 任务 `BLOCKED` 或缺少决策 | 暂停并等待用户 |

每个运行中的任务按这个门控执行：

1. 开发与测试设计并行。开发只改该任务允许的路径，先检查文件或云资源是否已存在。测试设计给出用例和命令，不替代实现。
2. 两边都返回后执行测试：单元、集成或该任务指定的回归。
3. 验证对照验收标准。验证不改业务代码。
4. 主控汇总开发产物、测试报告和验证结论，并更新 STATE。

任务验收：

- 通过：持久化代码路径、测试命令与结果、日志和检查点，然后回到轮询。
- 失败且允许自动修复：同一任务重试少于 2 次，原因是代码或测试问题。追加修复任务后回到轮询。
- 失败且需要人工决策：重试已达 2 次，或涉及 AWS 资源、架构、缺失信息。暂停。

子代理返回：改了哪些文件，验证命令和结果，未完成部分与阻塞。单个已确认的小任务可由主控按同样门控直接完成。

## 第四阶段：集成与阶段验收

1. 集成当前阶段产物，处理冲突并做联调。
2. 跑阶段测试、回归和构建检查。
3. 对照 `docs/requirement.md` 该阶段的验收标准。

验收不通过：生成阶段修复任务，回到轮询。通过且还有下一阶段：生成下一阶段计划，追加到队列；新阶段涉及云资源时先暂停确认。通过且没有下一阶段：进入第五阶段。

## 第五阶段：经验沉淀

全部阶段验收通过后才进入。把问题、原因和解决方案写入 KNOWLEDGE，并保留可复用的命令、规范和决策。分析和规划前先读这些记录。没有新经验时不写空话。

## 状态

合法状态：`PENDING`、`READY`、`RUNNING`、`REVIEW`、`DONE`、`FAILED`、`BLOCKED`、`PAUSED`。

STATE 头部保持：项目、更新时间、流程位置、会话状态、完成情况、检查点。任务状态一变就保存。未验证通过的任务不能标 `DONE`。

## 本项目约束

- 区域固定 `ap-southeast-2`。学习环境 Go 服务先跑 1 个 Fargate 任务。
- 预览环境共用 RDS，用独立 schema 隔离。
- 选型以 KNOWLEDGE 为准：CDK（TypeScript）、GitHub Actions + CodeBuild、SAM、ECS Fargate、RDS PostgreSQL。
- Phase 2 只负责把服务部署到 AWS。CI/CD、PR 环境和灰度分别属于 Phase 4、5、6。
- 本地数据库账号只用于本机 compose，不写入云上配置。
- WAF 关联 CloudFront、API Gateway 或 ALB，不挂在 Lambda 上。
- 用户没要求时不提交 git，不部署生产。
